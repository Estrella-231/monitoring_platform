第一章 系统概述
================================================================================

1.1 系统背景
-----------------------------------------------------------------
随着冷链物流行业的快速发展，对温度、湿度等环境参数的实时监测需求日益迫切。
传统的冷链监测方式依赖人工记录，存在数据不及时、无法预警等问题。
本软件旨在提供一个完整的冷链数据监测解决方案，实现对冷链环境参数的
实时采集、存储、告警和可视化分析。

1.2 系统目标
-----------------------------------------------------------------
本软件实现以下目标：
1) 实时采集温度、湿度等传感器数据
2) 数据可视化展示和历史查询
3) 灵活的告警规则配置
4) 多维度统计报表导出
5) 完整的审计日志记录

1.3 系统特点
-----------------------------------------------------------------
1) B/S架构，通过浏览器访问
2) 支持硬件和模拟两种数据采集模式
3) 前后端分离设计
4) RESTful API接口
5) 响应式Web界面

1.4 功能摘要（软著申请用）
-----------------------------------------------------------------
本软件采用B/S架构，实现冷链温湿度数据的实时采集、存储、
可视化展示和告警管理。支持多设备管理、灵活告警规则配置、
历史数据查询导出和统计分析报表功能。

第三章 功能详细设计
================================================================================

3.1 认证模块
-----------------------------------------------------------------
文件：backend/auth.py
功能：用户身份认证和权限管理

核心函数：
- hash_password(password: str) -> str
  使用BCrypt对密码进行哈希加密存储
  
- verify_password(password: str, hashed: str) -> bool
  验证用户输入的密码是否正确
  
- create_token(data: Dict) -> str
  生成JWT令牌，包含用户身份信息
  
- verify_token(token: str) -> Dict
  验证JWT令牌有效性，解析用户信息

安全机制：
- 密码使用BCrypt哈希存储，不可逆
- JWT令牌包含过期时间
- 支持Token刷新机制

3.2 用户管理模块
-----------------------------------------------------------------
文件：backend/users.py, API: /api/users
功能：用户CRUD操作

接口：
- GET /api/users - 获取用户列表（仅管理员）
- POST /api/auth/register - 用户注册
- POST /api/auth/login - 用户登录
- GET /api/auth/me - 获取当前用户信息

3.3 传感器数据模块
-----------------------------------------------------------------
文件：backend/sensor.py, API: /api/sensor/*
功能：传感器数据的采集和查询

接口：
- POST /api/sensor/data - 数据上报（采集端调用）
- GET /api/sensor/data - 数据查询（支持时间范围过滤）
- GET /api/sensor/data/{device_id} - 指定设备数据
- GET /api/sensor/latest - 最新数据
- GET /api/sensor/data/export/csv - CSV导出

数据模型：
- device_id: 设备标识（字符串）
- temperature: 温度值（浮点数，摄氏度）
- humidity: 湿度值（浮点数，%）
- timestamp: 时间戳（ISO8601格式）
- status: 设备状态（字符串）

3.4 告警模块
-----------------------------------------------------------------
文件：backend/alerts.py, API: /api/alerts, /api/alert-rules
功能：告警规则配置和触发

接口：
- GET /api/alerts - 告警记录查询
- GET /api/alert-rules - 告警规则列表
- POST /api/alert-rules - 创建规则
- PUT /api/alert-rules/{rule_id} - 更新规则
- DELETE /api/alert-rules/{rule_id} - 删除规则

告警规则：
- condition: 条件（gt大于, lt小于, eq等于, gte大于等于, lte小于等于）
- threshold: 阈值（数值）
- enabled: 是否启用（布尔值）
- notification_channels: 通知渠道（数组）

3.5 设备管理模块
-----------------------------------------------------------------
文件：backend/devices.py, API: /api/devices
功能：监测设备管理

接口：
- GET /api/devices - 设备列表
- POST /api/devices - 添加设备
- PUT /api/devices/{device_id} - 更新设备
- DELETE /api/devices/{device_id} - 删除设备

3.6 统计模块
-----------------------------------------------------------------
文件：backend/stats.py, API: /api/stats, /api/dashboard
功能：数据统计和仪表盘

接口：
- GET /api/stats - 统计摘要（设备数、告警数等）
- GET /api/dashboard - 仪表盘数据（趋势、分布等）
- GET /api/dashboard/trends - 趋势数据
- GET /api/dashboard/distribution - 分布数据

3.7 审计日志模块
-----------------------------------------------------------------
文件：backend/audit.py, API: /api/audit-logs
功能：操作审计追踪

记录内容：
- 操作人（字符串）
- 操作时间（时间戳）
- 操作类型（字符串）
- 操作内容（字符串）
- 操作结果（字符串）

3.8 报表模块
-----------------------------------------------------------------
文件：backend/reports.py, API: /api/reports
功能：数据报表生成

报表类型：
- daily_report: 每日统计
- weekly_report: 每周统计  
- alert_report: 告警统计

第四章 数据流设计
================================================================================

4.1 数据采集流程
-----------------------------------------------------------------
1) 采集端(Sensor)定时采集传感器数据
2) 数据POST到后端 /api/sensor/data
3) 后端验证数据格式
4) 存储到JSON文件
5) 检查是否触发告警规则
6) 如触发，生成告警记录并通知

4.2 Web请求流程
-----------------------------------------------------------------
1) 用户通过浏览器访问前端
2) 前端请求后端API
3) 后端验证JWT令牌
4) 处理业务逻辑
5) 返回JSON响应
6) 前端渲染显示

第六章 安全设计
================================================================================

6.1 认证安全
-----------------------------------------------------------------
- 密码使用BCrypt哈希存储，不可逆
- JWT令牌有过期时间（默认24小时）
- 支持Token刷新机制

6.2 接口安全
-----------------------------------------------------------------
- 需要认证的接口需要携带Authorization头（Bearer Token）
- 管理员接口需要admin权限
- API请求频率限制（可选）

6.3 数据安全
-----------------------------------------------------------------
- 用户密码加密存储
- 敏感操作记录审计日志
- 数据传输使用HTTPS（生产环境）

附录B：数据模型详细说明

B.1 用户模型 users.json
-----------------------------------------------------------------
字段：id, username, email, hashed_password, role, created_at, updated_at

-----------------------------------------------------------------

-----------------------------------------------------------------

B.4 设备模型 devices.json
-----------------------------------------------------------------
字段：id, name, location, type, status, created_at, updated_at

B.5 审计日志模型 audit_logs.json
-----------------------------------------------------------------
字段：id, user_id, action, details, ip_address, timestamp

附录C：数据库存储结构
================================================================================

C.1 JSON文件存储
-----------------------------------------------------------------
本系统使用JSON文件作为数据存储，无需配置数据库。

数据文件：
```
data/
├── users.json          # 用户数据
├── sensor_data.json    # 传感器数据
├── alert_rules.json   # 告警规则
├── alerts.json        # 告警记录
├── devices.json       # 设备数据
├── audit_logs.json   # 审计日志
└── reports.json      # 报表数据
```

C.2 数据关系
-----------------------------------------------------------------
- users.json: 存储用户信息
- devices.json: 设备归属用户管理
- sensor_data.json: 通过device_id关联devices
- alert_rules.json: 设备告警规则
- alerts.json: 告警记录关联alert_rules和device_id
- audit_logs.json: 审计日志关联users
